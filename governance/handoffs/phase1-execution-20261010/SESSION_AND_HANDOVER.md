## 3. 공용 자원과 실행 순서

문서·원본 비교·모의검증은 비의존 범위에서 병행한다. 같은 환경의 변경은 한 번에 하나로 진행한다. 앱의 다른 작업/Actions가 idle이라는 사실만으로 실제 서버의 타 작성자 부재를 판정하지 않는다. 이권욱이 해당 자원의 현재 사용을 확인하고 시작/반환을 같은 실행 기록에 남긴다.

| 회차 | 자원·주요 선행 입력 | 겹치면 안 되는 변경 / 후속 |
|---|---|---|
| E01 Delivery/APP/E2E | 운영 Harbor·Runner·대상 클러스터·DB; fresh scan/Robot/TLS·900초 실제 잔여·target/rollback·새 receipt | 같은 Registry stop/restart/credential 변경, DB restore, 대상 node/배치/정책 변경. 정상/Negative/rollback 별도 결과 후 최종 형상으로 Final Regression |

### 공통 실행 기록 — 별도 승인 서류를 늘리지 않음

같은 티켓/PR의 한 기록에 다음을 채운다. 비밀값이나 비공개 원문은 공개 댓글에 넣지 않는다.

### 실행 순서

1. **U01 회신 소비:** 콘솔 붙여넣기 실현성 또는 기존 허용 전달 경로를 확인한다. 아직 불가/미확인이면 그 방법으로 진행하지 않고 기존 대체 경로만 연결한다. clipboard/HGFS/방화벽/권한을 새로 열지 않는다. Harbor clone 제약을 db01 사실로 추정하지 않는다.
2. **수신 직전 확인:** 정확한 db01 식별·정상 계정/sudo·동시 경로 작성자·수신 위치/link/기존 파일 여부·남은 공간과 비공개 출력 위치를 확인한다. 기존 파일이 있으면 먼저 해시/소유/모드를 읽고 같은 파일이면 중복 전송하지 않는다. 다른 파일이면 덮어쓰지 않고 충돌로 기록한다.
3. **전달:** 확인된 방법으로 지정된 새 수신 위치에 원본을 전달하고 정상 계정의 기존 허용 범위에서 소유·모드를 맞춘다. base64는 공개 PR/로그/채팅에 게시하지 않는다. 아직 전달 경로가 확정되지 않아 이 문서는 자동 복사/디코딩 명령을 제공하지 않는다.
4. **수신 후 읽기 대조:** 아래 기존 도구의 출력·각 종료코드·KST 시각·파일 식별을 비공개 원본에 보존한다. 크기/해시/위치/소유·모드가 모두 맞아야 수령 완료다. 공개본에는 PASS/FAIL와 비공개 참조만 기록한다.

```bash
# db01, 정상 server08 + sudo; 전달이 끝난 뒤의 읽기 확인
TZ=Asia/Seoul date -Is
sudo stat -c '%U:%G %a %F %n' /var/lib/pgsql/fds-evidence
printf 'DIR_STAT_RC=%s\n' "$?"
sudo stat -c '%U:%G %a %s %F %n' /var/lib/pgsql/fds-evidence/fdsdb_backup_20260903.dump
printf 'FILE_STAT_RC=%s\n' "$?"
sudo sha256sum /var/lib/pgsql/fds-evidence/fdsdb_backup_20260903.dump
printf 'SHA256_RC=%s\n' "$?"
```

5. **종료:** 이권욱이 대조 결과/보관 책임/비공개 참조를 수신 기록으로 남기고 #21의 해당 잔여에 연결한다. 인수자 읽기 가능과 불필요한 접근 차단을 확인한다. 파일 수령이9/3 생성시각·DB버전·9/29 Restore 결과를 새로 증명하지 않는다.

실패 시: hash/크기/권한 불일치·경로 충돌·링크·전송 중단이면 수령 완료를 선언하지 않는다. 원 PC 사본과 기존 대상 파일을 보존하고 이번 불완전 수신본만 식별하여 별도 처리 판단을 받는다. 자동 재전송/덮어쓰기/삭제·운영 DB restore·서비스 재시작 없음. 새 회차가 필요하면 실패 원본과 구분한다.

### C01 — 기존 보관6묶음의 실효 접근통제

증적195의 원본 목록·해시·retention을 재사용한다. 보관자 회신은 H01/J01에서 이미 수신됐다. 이번 로컬 `Get-SmbConnection` 메타데이터 조회는 접근 거부였으며 파일서버 공유 ACL을 확인하지 못했다.

이권욱이 실제 공유 관리자/승인 조회 경로를 연결해 해당 공유의 허용 주체·그룹 구성/상속·공유 ACL·NTFS ACL의 결합 범위와 지정 보관자의 실제 접근을 읽기 확인한다. 비승인 접근 통제는 기존 정책/관리자 확인과 허용된 확인 범위로 입증하며 새로운 계정 생성·권한 상승을 시도하지 않는다. `Everyone FullControl` 파일 ACL만으로 외부 공개를 단정하지 않고, 로컬 읽기 성공을 승인 사용자만 접근 가능하다는 증거로 쓰지 않는다.

완료조건: 확인자·서버/공유 식별·조회 시각·허용 주체/실효 범위·보관자 접근·제한을 근거와 연결. 확인 전 새 민감 원본을 추가 전송하거나 접근통제 완료로 올리지 않는다. 기존 사본의 분석은 계속한다. 자원 회수기간 종료(현행10/26 계획)와 GitHub artifact 만료를 구분하고 자동 삭제하지 않는다.

## 5. 운영 인수·제3자 재현 회차 카드

참여자는 아직 미확정이다. 이하영/이재환에게는 아래 대상·역할별 참여 가능 범위/시간 또는 적격 대체자만 요청한다. 이권욱이 대신 준비할 문서·자료 대조를 원 담당자에게 재수행하도록 요구하지 않는다. 문서 리뷰/모의 설명과 실제 독립 수행은 별도다.

### O01 — DOC 핵심 Runbook의 제3자 재현

- 소비: H07/J08/S05·[#24](https://github.com/321Team/fds-project-baseline/issues/24). 이권욱이 원 AC의 핵심 절차와 최종 버전/대상·정상 접근·원복·증적 패키지를 제공한다. 준비 순서는 원본 찾기/버전·해시 대조 → 해당 핵심 절차 수행 → 결과 판정 → 종료/정리 → 재현에 막힌 문서 결함 기록이다.
- 대상 선정: 기존 backup/restore·장애/복구·운영 Runbook 중 미충족 핵심 항목을 AC와 대응시켜 선정한다. 원본 해시 확인만으로 전체 핵심 Runbook 재현을 통과시키지 않는다. 실제 변경 대상/필수 증적이 정해지지 않은 회차는 예약 확정하지 않는다.
- 참여 조건: 해당 재현 요건의 적격 제3자임을 확인하고 기존 정상 계정/필요 권한이 실제 가능해야 한다. 원 작성자가 자기 결과를 읽는 것을 제3자 실적으로 계산하지 않는다. 참여자가 원 작성자라면 해당 사례의 제3자 적격성을 별도로 판단한다.
- 완료: 실제 실행자·정확한 문서/도구 SHA·대상/시각·명령/rc·원본·독립 판정·정리 결과, 문서만으로 진행 불가했던 항목이 연결됨. 설명/드라이런만 수행하면 그 단계까지만 완료로 기록한다.
- STOP/복귀: 접근 부재·문서와 실제값 충돌·복귀점 미확인·예상 외 변경이면 중단하고 소유 자원만 기존 복귀 절차로 정리. 현장에서 새 정책/명령을 즉흥적으로 추가해 PASS 처리하지 않는다.

### O02 — Runner 두 번째 운영자와 queue/알림 운영

- 소비: H07/J08/S04·[Ansible61](https://github.com/321Team/infra-ansible/issues/61). PR77의 기존 운영자 카드와 승인 ephemeral 모델을 사용한다. 종료 후 등록 Runner0은 정상일 수 있으며 새 상시 Runner/broker를 도입하지 않는다.
- 참여 조건: 이권욱 외에 실제 공급·인증·회수까지 수행 가능한 운영자. 원본 보관자로 지정됐다는 이유만으로 이 역할을 부여하지 않는다. 정상 인증/폐기·비밀값 비공개·실패 시 인계 가능 범위를 확인한다.
- 최소 실습: 실제 수행 필요가 있는 고정 HEAD의 Job1개 선정 → fresh Run/Attempt/Job/labels/기존 Runner/세션 충돌 확인 → 기존 정상 방식의1회 공급/인증 → Job관측 → deregister·proxy/workspace·token packet 정리 → SHA/시각/rc/receipt 보존. 이미 완료된 CI를 운영자 실습만을 위해 무조건 rerun하지 않는다. 적절한 Job이 없으면 실습은 대기하고 준비 상태를 기록한다.
- queue/알림: 담당자·관측 시간/방식·기존 연락 채널·알림 인수/STOP/재인증·부재 시 대체 경로를 기존 카드와 연결해 실제 운영 기록을 남긴다. 폴링 주기·수신 채널을 임의 확정하거나 봇/자동화를 이번 문서로 설치하지 않는다. 순간 queued0은 상시 운영 완료가 아니다.
- 실패/복귀: 중복 Runner/Job·만료·틀린 labels/HEAD·정리 불확실 시 공급/재시도 중단. 원 회차 식별값으로만 회수하고 다른 실행자의 Runner를 삭제하지 않는다. 실제 인증·회수 불가 시 준비/일부 수행으로 남긴다.

### O03 — 최종 인수에 넘길 묶음

이권욱이 기존 티켓별 AC에 정확한 최종 형상·Runtime·독립 증적 리뷰·한계/유효 처분·보관·운영 인수 결과를 연결한다. As-built/Baseline 차이, Test/Evidence, Runbook, Known Issue, 버전 목록의 최종 동결은 관련 완료조건을 충족한 뒤 판단한다. 코드 병합/이번 문서 PR만으로 DOC Freeze·G1/G2/G3·Review·Sign-off·Close를 처리하지 않는다.

준비 산출물은 이3문서 한 묶음으로 유지한다. 새로운 팀 정책·단계별 승인 문서를 만들지 않고 원 티켓/PR에 실제 결과와 차이만 추가한다. 기존 담당자가 새 사실/참여를 제공하면 대응 ID에 연결하고, 미회신이 없는 작업까지 대기시키지 않는다.
