## 2. 끊김 없이 진행하는 순서

### A. 자료와 역할 인계

1. 이 PR에서 H/J 항목별 기존 근거·미수신을 확인한다. APP 승인값과 이미 있는 원본을 먼저 재사용한다.
2. credential 참조·dump 원본·Console와 같이 실제 보유자에게만 받을 수 있는 정보를 우선 수신한다. 비공개 원본 내용은 승인 경로에서 확인한다.
3. 이관된 잔여 범위와 실제 수신 확인을 구분해 기록한다. 본문 Status 현행화와 인수 결정을 혼동하지 않는다.

### B. 준비·리뷰 병행

1. Harbor installer/실험 입력과 Delivery plan/실패·복구 기대값을 준비한다. 필요한 코드는 변경 범위를 검토 가능한 PR로 제출한다.
2. 리뷰·자료 대기에는 DB/DR 수신 대조, 과거 한계 처분안, 기존 증적-AC 연결, K8S 복원안과 MON/SEC 최소 시험 행을 정리한다.
3. 원 담당자가 알 수 있는 사실이 없으면 추정 대신 미확인·확보 방법·영향을 남긴다. 필요한 부분만 대기하고 의존하지 않는 묶음으로 이동한다.

### C. 실환경 실행

1. 동일 호스트/클러스터/Registry·네트워크를 바꾸는 회차는 한 번에 하나로 잡는다. 독립 환경인지 확인된 문서·모의·읽기 준비는 병행할 수 있다. 타 세션의 진행 상태를 확인하지 않고 비중첩을 선언하지 않는다.
2. 각 회차 시작 전에 대상/버전/행위·입력 최신성·접근권한·기준 상태·백업/Console·성공/중단/복구를 확인한다. 실패 시 새 작업으로 덮지 않고 원본·실패 상태·복구 결과를 보존한다.
3. **Delivery의 선행조건은 사용하는 운영 Registry의 정상성·인증·승인 입력과 비중첩이다.** 격리 Harbor 자동복구 전체 완료를 새로운 공통 Gate로 만들지 않는다. 반대로 동일 Registry를 restart/stop하는 복구 시험과 Push/Deploy를 겹치지 않는다.
4. APP 정상 배포·Negative Gate·rollback은 별도 결과로 수집하되 같은 추적 가능한 입력 체계를 사용한다. 최종 운용할 버전/정책으로 Final Regression과 관련 metrics·보안 조건을 확인한다.
5. 이후 형상·정책을 바꾸면 영향받는 결과만 재검증한다. Drain·Node reboot·Pod restart·DB restore는 서로 대체되지 않는다. 한 창에서 수집해도 시험별 대상·시각·종료코드·원본은 분리한다.

### D. 인수와 Phase 2 준비 분리

1. 필요한 코드·증적 독립 리뷰, 제3자 핵심 재현·운영 인수, 실제 원본 수령을 확인한다.
2. 이권욱은 인수한 범위의 AC를 MET / NOT MET-RISK ACCEPTED / KNOWN ISSUE / APPROVED DEFERRED 등 기존 기준에 따라 판정한다. 미충족 사실·책임·재검토/완료조건·수신 티켓을 보존한다.
3. G1/G2/G3·Review·Close는 기존 선행조건과 유효 판정으로 연결한다. 새 승인 문서를 단계마다 만들지 않고 같은 기록에서 단계별 결과를 구분할 수 있다.
4. 다른 담당자는 실제 인계를 마친 영역부터 Phase 2 준비에 집중한다. Phase 2 준비 때문에 Phase 1 시험 환경이 바뀌면 영향/순서를 조정한다. 준비를 공식 Phase 2 Gate 통과로 표시하지 않는다.

## 3. 대기 조건별 다음 행동

| 대기 원인 | 대기할 부분 | 이권욱이 계속할 부분 |
|---|---|---|
| 비공개 원본 접근/해시 미확인 | 해당 자료의 수신·최종 인수 | 기존 소스/공개 Manifest 대조·다른 원본 인계·시험안 |
| Robot/Token/CA 입력 미확인 | 해당 credential 소비·변경 | 모의검증·배포 plan·rollback 입력 정리 |
| 기대 label/동시 호출·복귀값 미정 | 해당 파일 쓰기/relabel | 원본/후보 diff·복구 설계·다른 영역 준비 |
| reviewer 회신 대기 | 그 HEAD의 독립 리뷰 필수 병합/적용 | 미검토 코드의 허용된 정적/모의/격리 후보 시험·독립 문서 작업 |
| 실제 Console/복구점 미확인 | 그 복구점을 요구하는 위험 회차 | 비의존 읽기·패키징/시험 준비 |
| HA 변경 영향·귀속 기준 미정 | 해당 시험 또는 최종 AC 판정 | 영향분석·원본 비교·범위 밖 변경 없는 다른 준비 |
| 제3자/두 번째 운영자 미정 | 해당 실제 운영 인수·최종 완료 판정 | 코드/문서·실행 증적 정리. 자체 확인을 타인 실적으로 기록하지 않음 |

대기 해소는 실제 사실·근거로 판단한다. 무응답·일정 경과·PR 승인만으로 자료 수신이나 Runtime 성공을 생성하지 않는다.

## 5. 일정 재산정

이전 30~52시간/7~10작업일은 확정 일정이 아니다. PR32~40 완료분을 중복 산정하지 않는다. Harbor installer/H6 경로, ICR/SEC/MON의 남은 필수 시험 행, HA 변경 영향에 따른 회차가 정해지면 실제 구현·실행/복구·외부 대기를 나눠 재산정한다. 동일 증적을 쓰는 상·하위 티켓을 독립 공수로 더하지 않는다.

인계 답변을 받는 즉시 준비된 묶음을 이어가되, 본 문서는 무기한 모니터링/자동 wake-up을 설정하지 않는다. GitHub 리뷰·수신 기록과 현재 작업 요청에 따라 다음 실행을 이어간다.
