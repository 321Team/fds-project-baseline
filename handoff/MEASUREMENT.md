# Codex 이관 효과 측정

현재 향상률은 NOT_MEASURED다. 기존 Work에서도 자동화·스크립트 생성이 가능하므로
단순히 Codex 사용 여부만으로 더 빠르거나 정확하다고 판정하지 않는다.

| 대표 작업 | 비교 조건 | 비교할 결과 |
|---|---|---|
| 반복 Kit 재생성 | 같은 source Commit, 동일 파일·검증 범위 | Hash 일치, 직접 시간, 재작업 |
| 작은 Ansible/YAML 수정 | 같은 요구·난이도·AC, Runtime 대기 분리 | 정적 검사, review 수정량, 결함 |
| 증적 목록/Checksum 검토 | 동일 파일 수·수신 상태·판정 기준 | 누락 탐지, 오판, 검토 시간 |

`measurement.csv`에 Work/Cloud Codex 각 행을 채운다. 기존 완료 티켓의 현장 작업을
다시 수행하여 측정하지 않는다. 재현 가능한 오프라인 예제나 다음 실제 작업에서 수집한다.
실제 작업 비교 시 서로 다른 난이도·환경·모델·캐시·입력·검증 범위를 기록한다.

- 직접 시간: 사용자가 준비·지시·검토·수정에 쓴 분. 이관 설정 시간은 별도 기록 후 포함한다.
- 총 경과: 대기/모델 실행/환경 준비/검토 대기를 포함한 시간. 교육장 접근 대기는 별도 열.
- 재작업: AC 실패 또는 review 반영 횟수. 발견 결함과 이후 유출 결함을 분리한다.
- 절감률: `(Work 직접 분 - Codex 직접 분) / Work 직접 분 × 100`.
  Work 시간이 0이거나 비교 조건이 다르면 계산하지 않는다.
- 도입 판단: 일회성 설정비용을 포함한 누적 직접 시간, 결과 동등성, 결함 및 재검토 부담을 본다.
  3건은 초기 표본이며 일반적인 성능 보장으로 확대하지 않는다.
