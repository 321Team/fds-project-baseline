# 절차 간소화 검토 — 재현성·무결성·추적성 기준 (2026-09-29 회의 안건)

> 성격: 회의 입력 자료(제안). 정책·티켓·정본을 바꾸지 않는다. 채택 항목은 정책 변경 PR로 따로 반영한다.
> 작성: 2026-09-28, 이권욱 요청, Claude Code 작성(AI 사용). 수치는 2026-09-28 저장소·Issue 조회 기준이다.

## 0. 요약

- 이 프로젝트의 가치는 **재현성·무결성·추적성**에서 나온다. 간소화는 이 세 가지를 떨어뜨리지 않는 범위에서만 한다.
- 줄일 것은 **발행 횟수, 경과 보고, 수작업 재대조, 리뷰 대기, 작업창 병목**이다. 줄이지 않을 것은 **정본 체크섬, CR 동기화, 증적 봉인·독립 리뷰, AC↔증적 대응, 본문 보호, 리뷰된 SHA 연결**이다.
- 검토하면서 **재현성은 오히려 약한 곳**이 보였다. 콘솔 붙여넣기 증적, Runtime 변경이 소스보다 먼저 적용된 사례, 개인 PC에 보관된 원본, 기록되지 않은 AI 세션 판단이다. 간소화와 함께 보강해야 한다(5절).

## 1. 판단 기준

### 1.1 세 가지 가치의 정의

| 가치 | 뜻 | 확인 방법 |
|---|---|---|
| 재현성 | 같은 소스·입력·절차로 다른 사람이 같은 결과를 다시 만들 수 있다 | 소스(IaC·스크립트)와 실행 기록만으로 재실행 가능한가 |

## 4. 간소화 항목 상세

### S1. 정본 발행: 수시 발행 → 마일스톤 발행 + 누적 변경 대장

- **현행:** 변경이 모이면 수시로 발행한다(9월 6회).
- **변경안:**
  - 발행은 마일스톤에만 한다. 후보는 Phase 1 Close(10-06), Deliverable Freeze(10-23)다.
  - 발행 사이에는 `audit/change-ledger/`에 **누적 변경 대장**을 추가만 하는 방식으로 쓴다. 대상은 CR, 결정, 운영 드리프트, 티켓 속성 변경이다.
  - 발행 때 대장과 후보 Manifest를 1:1로 대조한다.
- **유지되는 통제:** I1(정본 콘텐츠는 발행 사이에 main에서 수정 금지, 현행 FAIL 검사), I2(대장이 누락 방지 장치)
- **기대 효과:** 발행 작업 약 6회 → 2회. 발행 준비 공수 감소
- **예상 위험:** K-01, K-02, K-13
- **선행조건:** 대장 양식 합의. A3(대장·CR 자동 대조)를 권장
- **정책 변경:** RELEASE_POLICY. 결정 주체는 이권욱(정본 Lead)

### S2. 증적 편입 범위: "모든 자료" → "판정 근거 필수, 진행 자료 선택"

- **현행:** 사전 점검·진행 로그·판정 근거를 모두 증적 저장소에 PR로 편입한다.
- **변경안:**
  - **AC 체크·Gate 판정·Decision 근거가 되는 자료는 예외 없이 증적 저장소에 편입**한다. 이 부분은 현행과 같다.
  - 판정에 쓰지 않는 진행 자료는 소스 저장소 `ops/`에 결과 파일과 SHA256SUMS를 두고, **main 병합 커밋의 고정 링크**로만 참조한다.
  - 나중에 그 자료를 판정 근거로 쓰게 되면, 그 시점에 증적 저장소에 편입한다.
- **유지되는 통제:** I3·I4(판정 근거는 봉인·독립 리뷰), 소스 저장소 main 이력(Git 불변성)
- **기대 효과:** 증적 PR 수와 리뷰 건수 감소(9월 89회 병합 중 일부)
- **예상 위험:** K-03, K-04
- **정책 변경:** EVIDENCE_POLICY. 결정 주체는 이권욱(증적 저장소 병합 담당). 증적 저장소 독립 리뷰 원칙(사용자 결정)은 바꾸지 않는다

### S3. 증적 리뷰 운용: PR별 개별 대기 → 묶음 리뷰 + 고정 체크리스트

- **현행:** PR마다 리뷰어를 기다리고, 리뷰 기준이 PR마다 다르게 서술된다.
- **변경안:**
  - 하루 1회(예: 17시) 대기 중인 증적 PR을 모아서 리뷰한다.
  - 리뷰 체크리스트를 고정한다. 항목은 EVIDENCE_POLICY 6개 확인 항목(원본 출처, 수신 바이트·해시, 실제 실행 여부, AC 대응, 누락·민감정보, 정정 이유)이다.
  - 해시·목록은 `check-evidence-layout.py` 결과로 확인한다(S5).
  - **Gate 전날에는 대기 PR 0건을 목표로 한다.**
- **유지되는 통제:** I3(PR별 정확한 SHA 독립 리뷰는 그대로)
- **기대 효과:** 문맥 전환과 대기 시간 감소
- **예상 위험:** K-05
- **정책 변경:** 불필요(운용 합의)

### S4. 티켓 기록: 경과 보고 → 결정 기록 중심

- **현행:** 진행 경과를 수시로 코멘트한다(상위 5개 티켓에 약 400건).
- **변경안:**
  - **반드시 코멘트:** 결정, 판정, AC 체크 변경, 일정·담당 변경, 차단 발생·해소. 근거 링크와 SHA를 적는다.
  - **코멘트하지 않음:** 진행 중 경과. 소스 저장소 `ops/<작업>/README.md`에 쓰고, 완료 시 링크 1건만 남긴다.
  - 코멘트 양식을 고정한다: `[결정|판정|변경|차단] 요지 / 근거(고정 링크) / 판단 주체 / AI 사용 표기`
- **유지되는 통제:** I4·I5, 결정의 추적성
- **기대 효과:** 코멘트 작성·읽기 부담 감소, 결정 기록이 경과에 묻히지 않음
- **예상 위험:** K-06
- **정책 변경:** TICKET_SYNC_POLICY 운용 조항 추가(경미)

### S5. 수작업 재대조 제거 → 도구 결과로 대체

- **현행:** PR 작성자와 리뷰어가 해시·파일 수·목록을 손으로 다시 센다.

- **유지되는 통제:** I1·I3(도구가 이미 검사). 판단 항목(AC 충족, 원본 진위)은 사람이 확인
- **예상 위험:** K-07, K-08
- **정책 변경:** 불필요
