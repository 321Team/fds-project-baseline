**경위와 손상:**

- **작성자 표기 footer:** 세션의 GitHub 쓰기 경로(에이전트 프록시)가 모든 본문 끝에 `_Generated by [Claude Code](https://claude.ai/code)_` footer를 붙였다. #7·#35는 이 footer 외에는 계획과 일치한다.
- **CRLF 변환:** 같은 경로가 CRLF를 LF로 바꿨다. 보관 원문 SHA-256은 LF 기준으로 계산돼 있으므로 이 변환은 해시 대조에 영향이 없다(#11에서 확인).
- **링크 변형:** 같은 경로가 일부 Markdown 링크의 URL을 ``` `` ``` 로 감쌌다. 그 결과 링크가 코드 표기로 깨졌다.
  - #11: 현행 영역 링크 5개. 한글 앵커가 있는 증적 링크이며, 퍼센트 인코딩 재시도에서도 변형됐다.
  - #16: 현행 영역 링크 1개와 보관 원문 링크 1개. 둘 다 v3.1.17 Ticket Update Pack 링크다. **보관 원문 SHA-256 대조가 깨졌다.**
- 변형 규칙을 예측할 수 없어 일괄 반영을 중단했다. 이후 세션 자동 권한 판단이 추가 외부 쓰기를 차단했다.

**복구 방법:** GitHub 웹 UI(프록시 미경유)에서 해당 Issue 본문을 `repair/repair-issue-<번호>.md` 전체 내용으로 교체한다. 또는 편집 화면에서 ``` ``https ```의 ``` `` ```와 링크 끝 ``` ``) ```의 ``` `` ```를 지운다(#11 5곳, #16 2곳). 복구 후 확인 기준은 두 가지다. 첫째, 보관 원문 해시 표기와 LF 정규화 원문 해시가 일치해야 한다. 둘째, 본문에 ``` ``https ```가 0건이어야 한다.

## 4. 신규 저장소 준비 — 생성 차단

- `infra-terraform`·`infra-rosa` 생성 시도 결과 GitHub MCP와 API 모두 **403**이었다. 이 세션은 연결된 저장소에만 쓸 수 있어 조직 단위 저장소 생성이 불가하다.
- 초기 구성 파일은 `proposed/<저장소>/`에 준비했다. 정책은 기존 저장소와 동일하게 맞췄다:
  - `docs/REVIEW_POLICY.md` = infra-dns 최신본(PR #93 병합 반영) 그대로
  - `.github/PULL_REQUEST_TEMPLATE.md` = infra-pki와 동일
  - `.github/CODEOWNERS` = 기존 형식(`Review routing only`)이며 Lead를 앞에 둔다
  - `.gitattributes`·`.gitignore` = fds-msa/infra-pki 기준에 Terraform State·tfvars, OpenShift 자격증명 차단을 추가
  - README = 책임 티켓(2026-09-23 Issue 속성표 기준 Lead/Support)·저장소 경계·비밀정보·변경 절차

- Branch 보호: `main`에 PR 필수, 승인 1건, CODEOWNERS 리뷰, force push·삭제 금지를 권장한다. GitHub 요금제 제약으로 적용할 수 없으면 기존 저장소처럼 수동 통제로 기록한다. 설정이 강제 적용됐다고 표시하지 않는다.
- Actions: `GITHUB_TOKEN` 기본 읽기 전용을 권장한다. Self-hosted Runner는 연결하지 않는다(infra-cicd Runner 경계 유지). AWS 자격증명을 저장소 Secret에 두지 않는다. 방식은 P2-IAC-01 State/자격증명 결정(OIDC 등)을 따른다.
