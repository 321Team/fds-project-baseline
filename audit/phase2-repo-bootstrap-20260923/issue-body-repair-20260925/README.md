## 3. 확정 본문 (`bodies/`)

기준 본문은 "직전 정상 revision + 손상 편집의 정당한 추가분(손상만 제거)"이다(지침 §4-1).

| Issue | 확정 본문 | 키트 후보와의 관계 | 검증 |
|---|---|---|---|
| #9 | 9/24 신규 절(후보 1~16행) + 직전 정상 revision 전체 | 후보와 따옴표 14자만 다르다(`“ ”` 7쌍 복원) | 신규 절 뒤의 본문은 직전 정상 revision과 바이트가 같다. 보관 원문 SHA-256 `43f83489…94201` 일치 |
| #74 | 키트 후보와 같음 | 동일(`3ef0a477…649b1`) | 직전 정상 revision과의 차이는 신규 절 추가와 `End` 값뿐이다 |
| #75 | 키트 후보와 같음 | 동일(`ef53343b…c6087`) | 직전 정상 revision과의 차이는 `Start`·`End` 값뿐이다 |

세 건 모두 `&lt;`·`&gt;` 0, 단독 ``` `` ``` 0, CRLF 0, footer 0이다.

남은 한계 [미확인]: #9의 9/24 신규 절에는 곧은 따옴표 1쌍(`"API 표본 1…"`)이 있다. 이 절은 정상 revision이 없어서, 원래 둥근 따옴표였는지 판단할 수 없다. 추측으로 바꾸지 않고 관찰된 문자를 그대로 둔다. #74의 9/23 신규 절도 대조할 원본이 없다. 다만 손상 신호는 0이다.
