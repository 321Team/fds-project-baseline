## 3. Lead 실행 — 편집 이력 조회 (쓰기 없음)

전제: Windows PowerShell 5.1, `gh` 로그인. 브랜치 ZIP은 브라우저로 받는다(9/23 절차와 같다).

1. 이 폴더에서 `powershell -ExecutionPolicy Bypass -File .\fetch-edit-history.ps1`을 실행한다.
   - 정상 출력: `READ #9 …`, `READ #74 …`, `READ #75 …` 세 줄 뒤에 `DONE read-only`
   - `STOP`이 출력되면 멈춘다. 쓰기가 없으므로 되돌릴 것은 없다.
2. 생성된 `edits\` 폴더(`edits-<n>.json`, `issue-<n>.json`, `SHA256SUMS.txt`)를 ZIP으로 묶어 세션에 전달한다.
   - 이 파일에는 Issue 본문 이력만 들어 있다. 토큰은 들어 있지 않다.
   - 저장소에는 커밋하지 않고 분석 결과만 기록한다.

세션 분석: `python3 analyze-edits.py <edits 폴더> --dump <출력 폴더>`

- revision별로 편집 시각, 편집자, 길이, SHA-256(LF), 손상 신호(A `&lt;`/`&gt;`, B ``` `` ```, footer)를 출력한다.
- **처음 손상된 revision**과 **그 직전의 정상 revision**을 표시한다. 결과는 `analysis.json`에 저장한다.
- 원문에 원래 ``` `` ```가 있을 수 있다. 그래서 ticks 값은 revision 사이에서 늘어난 양으로 판단한다.
