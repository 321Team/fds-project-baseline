## 현재 실행·검토 상태

9/1 격리 신규 DB의 pg_dump→TRUNCATE→pg_restore 13건 재현과 9/3 dump 보관이 담당자에 의해 보고됐다. 운영 db01 원본 변경을 뜻하지 않는다. 백업 원본 해시 독립 검증, 정식 Evidence 등록·Runbook·정본 Restore 후 E2E는 미완료다. 사전 착수 보고만으로 To Do를 자동 변경하지 않는다.

근거: [Issue #21](https://github.com/321Team/fds-project-baseline/issues/21), Issue 갱신 시각 `2026-09-10T04:02:43Z`. 댓글·승인 기록과 본문 보관본은 `../source-snapshot.json`에 보존하고 실제 Gate는 해당 증적·승인 범위로 판정한다.

## 적용 기준

- Baseline v3.1.18의 현행 설계·Interface·Gate와 아래 Scope/Acceptance를 함께 적용한다.
- 이력의 당시 PASS·Done은 원래 범위에 한정한다. 후속 Runtime 또는 승인자를 새로 생성하지 않는다.

# User Story

데이터 담당자로서 PostgreSQL 논리 Backup으로 거래·FDS 데이터를 복구한다. 이를 통해 단일 DB 구조에서도 최소 복구 가능성과 절차 재현성을 입증한다.
