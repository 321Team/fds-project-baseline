## 프로젝트 성과와 배운 점

마지막으로, 프로젝트의 구축과 검증 과정을 돌아보겠습니다.

이번 프로젝트에서는 완료 기준을 먼저 정하고, 실행 증적을 바탕으로 보안 통제와 기능이 기대대로 동작하는지 확인했습니다.
DB 백업을 격리 환경에 복원해 데이터를 대조했고, 변경 이력을 남겨 검증 과정을 추적할 수 있도록 했습니다.

진행 과정에서는 리뷰와 증적 관리에 필요한 시간을 충분히 고려하지 못해 일정 조율에 어려움이 있었습니다.
이를 개선하기 위해 사전 검증 리뷰는 간소화하되 런타임 코드 리뷰는 유지하고, 코드 변경과 실제 환경 적용의 승인 절차를 구분했습니다.

이 경험을 통해 좋은 절차는 품질을 지키면서도 팀이 정해진 일정 안에서 실행할 수 있어야 한다는 점을 배웠습니다.
기술을 선택할 때도 구축 자체뿐 아니라 운영과 복구에 필요한 조건까지 함께 고려해야 한다는 교훈을 얻었습니다.

이상으로 발표를 마치고, 질문을 받겠습니다.

## 후속 연결

이미 반영한 개선은 중복 리뷰 축소, 코드 변경과 실제 환경 적용 승인 분리, 관련 변경의 일괄 검토다.
남은 기술·복구·회수 Action은 [순차 정리 현황](../phase2/preparation/20261025/closeout-status.md)에 Owner와 완료조건을 남긴다.
회고의 편입은 실제 Action의 수행·인수 기록을 대체하지 않는다.
